腾讯企点营销云 MAGIC AI

从功能驱动到意图驱动，探索 Agent-first 的交互体验范式

产品
腾讯企点营销云 MAGIC AI —— 面向企业增长的 AI 原生营销智能体平台
角色
负责 Agent 基础配置与任务协作体验，主导营销云 AI 设计体系建设及 AI-ready 工作流升级。
时间
2024 — 至今
关键词
AI 产品体验设计 / 意图驱动 / Agent-first / Multi-Agent / HITL（人在回路）

01 产品与体验

MAGIC AI：把分散的营销能力组织成完整增长任务

从营销工具集合，到智能增长操作系统。 企业通常并不缺少营销工具，真正困难的是如何把分散的数据、策略、知识和执行能力持续组织起来，形成可以重复使用的增长能力。

先从一场秋冬换季沉默会员召回活动，看看 Agent 如何把增长目标变成可执行方案。

MAGIC AI 把企业数据、营销经验和执行工具组织成可协作、可治理的智能增长系统。

Agent-first：从找功能，到提目标。

面对适合智能体承接的增长任务，用户先表达目标，由 Agent 组织执行步骤，人保留关键决策权。让这种协作方式更易理解、可控、可复用，是 MAGIC AI 持续探索的体验方向。

02 发现与定义

为什么“意图”成为产品转型的核心问题

产品转型的目标，不是把每个功能都改造成对话入口，而是让 Agent 承接跨模块的完整营销任务。对运营人员来说，关键体验问题是：目标、人群、规则和修改记录能否在任务推进中持续被理解、确认与沿用。

从一场大促旅程，看见完整意图如何损耗

以会员运营做一场大促为例，看同一份业务目标如何在整条链路里损耗。

核心发现是，传统 SaaS 按功能组织能力，会员运营必须自己维持一条跨模块的完整意图。

设计机会是，让系统从业务目标出发组织步骤，把分散能力串成可理解、可确认、可复用的任务链。

从产品转型到双向意图对齐

产品侧让用户从经营目标而不是功能入口发起任务；体验侧让 Agent 解释自己理解的目标与约束，允许用户在执行前补充、修正并确认。两者共同解决跨模块任务的上下文断点。

落到 AI 产品设计上，有三点需要注意。

1意图完整

说清要服务谁、遵守什么规则、做到什么结果。

2过程可控

AI 先讲出理解和依据，关键步骤再由人确认。

3结果可用

方案能改、能执行，经验和产出落到企业知识库与资产。

03 体验策略

从增长任务出发，选择 AI 的介入方式

产品层先判断增长任务发生在持续洞察、策略决策还是跨步骤执行；体验层再根据任务由谁发起、意图是否明确、复杂度和出错代价，选择内嵌式 AI、协作式 Copilot（AI 协作助手）或 Multi-Agent（多智能体协作）。三者不是线性升级关系，而是面向不同任务条件的协作选择。

结合业务流程与行业交付反馈，三类策略分别对应持续发现机会、共同澄清规则和完成复杂任务。设计重点不是展示 AI 能做多少事，而是匹配用户当前的决策责任与操作成本。

1. 洞察：用内嵌式 AI 帮用户看清经营机会

需求洞察

增长要持续判断哪些人群值得经营、上一场复盘能否复用。判断散落在多个模块，运营自行串联的门槛高。

产品体验

针对持续性、低打扰的经营洞察，将 AI 建议嵌入已有工作台，而不是要求运营反复发起对话。将人群信号、复盘结果与建议动作集中呈现，保留判断依据和进入下一步的选择权。

2. 决策：用协作式 Copilot 形成可信方案

需求洞察

前场交付要大量协助企业整理并配置规则。材料如何拆解、冲突和适用范围如何处理，需要一起澄清。

产品体验

规则材料可能存在歧义与冲突，因此采用人机协作而非直接自动执行：AI 负责提取信息、提示冲突和适用范围，运营负责澄清与确认；只有确认后的规则才进入策略库，供后续任务复用。

3. 行动与验证：用 Multi-Agent 完成复杂增长任务

需求洞察

真实任务里过程信息过多，活动分支也比演示更复杂。潜在诉求是中途可改，失败不必退出重做。

产品体验

面对跨步骤的长任务，由主 Agent 维护整体目标、专业 Agent 分工处理。界面优先展示任务状态、关键产物和待确认事项，低价值过程默认折叠；当条件变化或执行失败时，支持用户调整后继续，而非从头重做。

04 基础体验

Agent 交互体验范式

三种 AI 介入方式不同，但用户始终需要回答三个问题：Agent 能做什么、目前准备怎么做、交付结果是否可信且可用。因此，将任务发起、协作确认和结果验收中的共性决策，沉淀为一致的交互范式。

1. 意图可见

通过任务示例、能力范围和输入引导，帮助用户明确可提出什么目标，以及需要补充哪些人群、条件与约束。

2. 过程可介入

非关键执行过程默认收起，关键计划、待确认动作与异常状态保持可见；用户能够查看、修改或确认下一步。

Agent 执行过程与过程反馈

从 Markdown 全量平铺，转向按用户决策需求分层；再补充执行轨迹、任务进度与关键节点反馈。

3. 结果可用与沉淀

结果不仅要能查看，还应支持核对与调整；经用户确认的规则和产物再进入企业知识与资产体系，供后续任务复用。

主路径上的共性解法

将任务表达、协作确认与结构化产物抽象为三类基础组件，统一不同 Agent 的状态反馈、确认方式与结果呈现，降低跨场景使用时的学习成本。

05 验证与总结

验证意图驱动，沉淀可复用的体验能力

从功能驱动走向意图驱动，要在真实任务中检验 Agent 是否准确理解意图、交付结果是否可用。用户愿意持续使用，产品才有健康增长的基础。

1. 从交付反馈到体验迭代

交付反馈暴露了规则分散、过程信息冗余与复杂分支难处理的问题，推动规则配置 Copilot、三栏任务空间和结构化产物的迭代。体验验证则围绕任务完成、关键操作质量与业务效果展开。

2. 把 AI 融入团队设计工作流

不同角色借助 AI 产出界面后，质量与规范容易出现差异。为此，将组件规则、页面范式和使用方法整理为 AI 可理解的设计上下文，用于方案探索与规范检查；团队负责业务判断、设计取舍和规范维护。

3. 从设计 Agent 产品，到设计人和 AI 的工作方式

围绕企业增长任务，MAGIC AI 持续探索意图驱动的协作体验，并推动产品在多个营销场景中落地。2026 年营销云整体业务签约金额增速 +35%，已签约订阅制 KA 客户 160+ 家。

在产品体验层面，持续关注 KA 客户的实际采用、有效任务完成与后续复用，并结合关键确认、异常恢复等交互反馈，优化 Agent 的可理解性、可控性与任务完成体验。

Agent-first 的核心，不是让所有操作都变成对话，而是让 AI 在合适的任务中承接复杂过程，让用户专注于判断和决策。
